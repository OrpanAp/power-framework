Security & authentication

Understand server-side sessions, password hashing, role checks, CSRF protections, login throttling, and optional two-factor authentication.

Sessions

Session data is stored server-side in the database; the browser receives a random session identifier cookie. The identifier is regenerated on login and sensitive account changes. 

req.session.get('key', defaultValue);
req.session.set('key', value);
req.session.forget('key');
req.session.flash('success', 'Saved!');
req.session.regenerate();
req.session.destroy();

Protect routes

app.get('/dashboard', auth.requireAuth, HomeController.dashboard);
app.get('/login', auth.requireGuest, AuthController.showLogin);
app.group('/admin', [auth.requireRole('admin')], (r) => {
  r.get('/', AdminController.dashboard);
});

Password and account protection

  • Password hashes use Node.js scrypt with a random salt.
  • Sessions support idle and absolute expiry.
  • CSRF tokens and Origin checks protect unsafe requests.
  • Security headers and request-size limits provide additional guardrails.
  • Login throttling and account lockout slow repeated guessing.
  • Optional TOTP two-factor authentication includes single-use backup codes.

Enable administrator 2FA

Review REQUIRE_ADMIN_2FA in your environment configuration. Users manage their authenticator from the account security area. Treat backup codes and session secrets as sensitive credentials.

These are security building blocks, not a guarantee that your application is secure. Review the source, keep Node.js updated, protect secrets, configure HTTPS, and test the deployment against your threat model.
